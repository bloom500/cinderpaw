## Bugs found BY this smoke (all fixed + tested)

1. **approve read policyId from `msg.id`** — the roundtrip correlation UUID — so every CLI/API approve failed with `unknown proposal: <uuid>` (fix: 08e3627).
2. **propose body flattened over the envelope** — the sidecar handler reads `msg.document`; the API route now wraps the posted policy as `{document: …}`.
3. **genesis started the 24h auto-adopt cooldown** — genesis is written with actor `system` but is not an auto-adoption (§5); every fresh install's first tightening proposal queued for 24h. `cooldownActive()` now skips the genesis row (parentId null). Regression test added.
4. **`governance verify` printed `✗ unknown error` on failure** — the generic `!ok` guard ate the payload before the verify renderer; a failed verify now prints the per-chain/per-file report and exits 1.

## Approve leg — covered indirectly (by construction)

A live `governance approve` demo needs a proposal on the human path (relaxing/mixed), which is impossible from the current state: the active policy is the genesis document sitting AT the G0 budget walls, so any relaxation is a G0 violation (verified live: `propose` with episodeMaxIterations 1200 → `✗ G0 violation … a proposal needing clamps is a buggy or hostile proposer`), and any tightening now rides the 24h cooldown started by gp-3's auto-adoption. The approve wire path ({policyId} through the roundtrip flattening into the sidecar handler) is byte-identical to reject's, which passed live; the FSM approve itself is covered by the 45-test governance suite (every `bootstrap()` approves a proposal). First natural approve will occur when a tightened policy is later relaxed back.
