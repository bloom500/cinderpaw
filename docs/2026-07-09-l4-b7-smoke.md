## Bug found during smoke (3): VERSION fallback in compiled sidecar
(fixed, uncommitted)

The first eval attempt after the dream cycle ended rejected
`mod-retrieval-demo-01` at manifest validation with the floor
`compat.runtime >= 2026.6.17`. Root cause: the compiled sidecar reported
`0.0.0-dev` because the source used
`readFileSync(new URL("../package.json", import.meta.url), "utf8")`,
which bun's `--compile` cannot resolve at runtime — the relative URL
points to a path that no longer exists in the single-file binary. Every
module manifest's `compat.runtime` floor therefore failed.

Fix (in `FeralAgent/src/index.ts`, necomis): static import of
`package.json` with the `with { type: "json" }` attribute so bun
bundles the JSON into the binary; the `FERAL_VERSION` env override is
preserved for dev/testing. Verified the rebuild contains the real
version string (`2026.7.5`).

Two follow-on cleanups also landed in the same edit (would have broken
`tsc --noEmit` under `noUnusedLocals: true` otherwise):
- `index.ts:12` — drop the now-dead `readFileSync` from the
  `node:fs` import (the version path no longer uses it).
- `index.ts:2392` — the `version` subcommand was still re-doing
  `fs.readFileSync(new URL(...))`; rewritten to use the new `VERSION`
  constant so the subcommand reports the real version too.
