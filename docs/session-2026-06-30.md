## 1. The shift that happened today

Until this session, Feral was understood as "another AI agent" — a
local-first assistant with tools, memory, and planning. A useful tool
in the same category as Hermes Agent, OpenClaw, OpenHands, Cursor.

**That framing is gone.**

Feral is now **Gen 3: a Bounded Evolution Runtime** (FER) that AI agents
can run on. The runtime is the product. The Personal Agent is one
consumer.

```
Gen 1 — Chatbot       GPT, Claude, Gemini            Fixed model
Gen 2 — Agent         Hermes, OpenClaw, Cursor      Tools + memory + planning
Gen 3 — Evolution     Feral                          Memory + Governance + Genome +
  Runtime                                            Champion + Species + Ratchet +
                                                     LoRA + Lineage + Contract + Journal
```

Feral is **not** AGI. The "bounded" in BRSI is the contribution:
safe, measurable, reversible improvement within user-defined limits.
The limits are the interesting part.

## 3. Architecture insights that emerged

### 3.1 Microkernel pattern (ADR-0010)

The 8 production modules are independent. `confidence.ts` doesn't know
`budget.ts`. `journal.ts` doesn't know any other module. The kernel
(engine + EventBus + ratchet + champion) orchestrates by composition:

```
KERNEL: engine.ts + EventBus + ratchet + champion
       │
       ├── confidence.ts      (no imports from rsi/)
       ├── budget.ts          (type-only: DreamStage from journal.ts)
       ├── journal.ts         (no imports from rsi/)
       ├── provenance.ts      (type-only: RsiBridge from bridge.ts)
       ├── personal-fitness.ts  (no imports from rsi/)
       └── fitness.ts         (type-only: FitnessVector from journal.ts)
```

Adding a new module doesn't touch existing modules. The kernel's only
job is composition.

### 3.2 FER (Feral Evolution Runtime) — ADR-0009

"Feral Agent" was imprecise. The runtime is FER; the user-facing AI
is "Personal Agent" that runs on FER. Foundation-model-agnostic.
"FER + Gemma", "FER + Qwen", "FER + Llama", "FER + tomorrow's
models" — all become natural framings.

When asked "is Feral an AI agent?", the right answer is: "No — Feral
is the runtime that AI agents run on, and that can make them better
over time in controlled ways."

### 3.3 Layers for presentation, DAG for engineering — ADR-0008

The 7-layer model (L0–L6) is intuitive for humans — it describes the
**autonomy scale** (what the engine is allowed to do, and at what
scrutiny). But the runtime is a dependency graph, not a stack. Both
views live in `docs/brsi-spec.md`: §5 is layers, §10 is the DAG.

### 3.4 Invariants as the contract

Every safety claim is a HARD or SOFT invariant with four pillars.
HARD = violation = HALT / Rollback. SOFT = warning + ADR + version
bump. The linter enforces the discipline.

### 3.5 Personal Fitness ≠ global benchmark

Sakana / Darwin Gödel Machine optimize global capability on public
benchmarks. Feral optimizes per-user usefulness (ADR-0005).
Local-first is **required** for Personal Fitness to work — cloud sync
makes it a privacy problem; local-first makes it a personal dataset.

## 8. The discipline (what NOT to do)

Per Opus handoff brief §10.1:

> **Do not rewrite existing pure modules unless an invariant is
> violated. Prefer composition over replacement. Preserve additive
> migration paths.**

Concretely:
- Don't rename `evaluateGate`, `assertCanSpend`, `scoreToFitnessVector`, `computePersonalFitness`, `appendJournal`, `rsiProvenanceGraph`.
- Don't change the signatures of `GateDecision`, `BudgetDecision`, `FitnessVector`, `JournalEntry`, `ProvenanceNode` without an ADR.
- Don't reimplement the bootstrap in `confidence.ts` (paired bootstrap, Cohen's d, Mulberry32 PRNG — the math is the math).
- Don't collapse `budget.ts`'s peak/cumulative distinction.
- Don't unify Personal Fitness adapters.

If you find yourself wanting to "improve" one of these modules, write
an ADR first. The discipline is what makes the orchestration safe.

## 9. A note on what this means

Feral was a collection of interesting ideas. Today it became **a
coherent architecture with a clear research direction**.

The "bounded" in BRSI is the contribution — not AGI, not open-ended
RSI, not unbounded self-modification. A system that improves itself
**safely, measurably, and reversibly**, within user-defined limits.

When someone proposes "let's remove the confidence gate, it slows
evolution", the answer is in `docs/invariants.md` I6 and
`docs/feral_philosophy.md` Why human governance? — the PR would have
been considered and rejected before it was opened. That's what the
philosophy doc is for.

When someone proposes "let's add a new module", the answer is in
ADR-0010: it goes in the kernel if it's orchestration, otherwise it's
a peer module with explicit invariants.

When someone proposes "let's swap models", the answer is in
ADR-0009 + FERAL_PHILOSOPHY.md: FER + {model}. The runtime is
foundation-model-agnostic. 90% of knowledge persists across swaps;
10% (LoRA) is re-bootstrapped from Personal Fitness signals + the
personal eval suite.

The next agent that picks this up finds:
- 11 ADRs that explain decisions
- 15 invariants that enforce safety
- 8 modules that are frozen (per discipline guard rail)
- 1 linter that checks invariant coverage
- 1 brief that hands off the work

That's not "another AI project". That's research infrastructure.
