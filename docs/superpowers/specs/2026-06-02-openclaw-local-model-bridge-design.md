# OpenClaw ↔ Feral Local Model Bridge

**Date:** 2026-06-02  
**Status:** Approved

## Goal

Make OpenClaw the agent execution engine for Feral, backed by Feral's local llama.cpp model. Users get full OpenClaw agent capabilities (sessions, memory, tools, skills) running entirely on-device. Feral's React UI is the chat interface; OpenClaw is invisible infrastructure.

## Architecture

```
[Feral React UI]
      ↓  run_agent IPC — Tauri Channel (SSE)
[lib.rs → openclaw::run_openclaw()]
      ↓  POST /v1/chat/completions  model="openclaw/default"
[OpenClaw gateway  :18790]   ← OPENCLAW_CONFIG_PATH=~/.feral/openclaw-feral.json5
      ↓  default agent → feral/current
[Feral Ollama API  :11435]   ← api::serve(), started at launch
      ↓
[llama.cpp / ModelManager]
```

Port 18790 (not the OpenClaw default 18789) avoids conflict with any existing OpenClaw instance the user may be running independently.

## Config File — `~/.feral/openclaw-feral.json5`

Generated by Feral at startup. Overwritten each launch (token regenerated per session).

```json5
{
  gateway: {
    port: 18790,
    bind: "loopback",
    auth: { mode: "token", token: "<session-token>" }
  },
  models: {
    providers: {
      feral: {
        baseUrl: "http://localhost:11435/v1",
        models: [{ id: "current" }]
      }
    }
  },
  agents: {
    defaults: {
      model: { primary: "feral/current" }
    }
  }
}
```

Feral's `v1_chat_completions` handler ignores the model field and always serves the loaded model, so `"feral/current"` is a stable stable alias regardless of which GGUF is loaded.

## Startup Sequence (`lib.rs` setup)

Order matters — Feral API must be ready before OpenClaw tries to route to it.

1. Start Feral Ollama API (`api::serve()`) on port 11435 in a background Tokio task.
2. Generate session token (`openclaw_sidecar::generate_token()`).
3. Write `~/.feral/openclaw-feral.json5` with the token and provider config above.
4. Find OpenClaw binary (PATH → bundled, existing logic unchanged).
5. Start OpenClaw sidecar: `openclaw gateway` with env vars:
   - `OPENCLAW_CONFIG_PATH=~/.feral/openclaw-feral.json5`
   - `OPENCLAW_GATEWAY_TOKEN=<token>` (kept for any direct-connect callers)
6. Persist token and `gateway_endpoint_override: "http://localhost:18790"` to `~/.feral/openclaw_connection.json`.

On `RunEvent::Exit`, the existing child-kill logic handles OpenClaw teardown. The API server Tokio task is cancelled via the `AppState` shutdown signal (or process exit).

## New Rust Module — `openclaw_config.rs`

Single responsibility: write `~/.feral/openclaw-feral.json5`.

```rust
pub fn write_feral_config(token: &str) -> Result<()>
```

Uses `paths::feral_dir()` (already exists). Writes the JSON5 config above. Called from `lib.rs` setup between steps 2 and 4.

No reading/parsing of `~/.openclaw/openclaw.json`. Feral's config is standalone.

## `openclaw_sidecar::start_sidecar` — Signature Change

Add `config_path: &Path` parameter. Passes `OPENCLAW_CONFIG_PATH` env var.

```rust
pub fn start_sidecar(binary: &Path, token: &str, config_path: &Path) -> Result<Child>
```

## Onboarding Changes (`AgentsOnboarding.tsx`)

### `handleSave` — saves agent with runtime set

```ts
const cfg: AgentConfig = {
  name:               agentName.trim(),
  system_prompt:      preset?.system_prompt ?? DEFAULT_SCRATCH_PROMPT,
  model_id:           loadedModel?.path ?? '',
  tools:              preset?.tools ?? [],
  preferred_runtime:  'openclaw',   // ← new: always route through OpenClaw
};
```

### DoneStep — warmup + status

`DoneStep` receives `agentId` (already wired). On mount, fires `tauri.openclaw.warmupAgent(agentId)`:

- **Warmup succeeds:** shows "✓ Running on [model name]" in green  
- **Warmup fails (no model loaded):** shows "Agent saved. Load a model in the Models tab to activate."  
- **Warmup pending:** shows spinner

Warmup result is already saved to `agent.openclaw_ready` by `openclaw_warmup_agent` on the backend — no extra persistence needed.

## AgentCard UI Cleanup

### Remove `RuntimeSelector`

The "Local Feral / OpenClaw" toggle is removed. All agents run through OpenClaw. `AgentRunPanel` drops the `runtime` state and `RuntimeSelector` component.

### `AgentRunPanel` — single run body

`LocalTestBody` and `OpenClawTestBody` are replaced by a single `AgentRunPanel` body that:
- Uses `tauri.agents.run()` SSE (the `run_agent` command — routes through OpenClaw)
- Removes amber/experimental styling
- Keeps the same prompt input + streaming output display

### `OpenClawBadge` → `AgentStatusBadge`

Rename and simplify. Shows:
- `openclaw_ready === true` → green "Ready" badge
- `openclaw_ready === false` → amber "Load a model" badge  
- `openclaw_ready === null/undefined` → nothing (untested)
- `gatewayUp === false` → subtle "Gateway unavailable" (unchanged)

## `run_openclaw()` — No Change

Still sends `model: "openclaw/default"`. OpenClaw's default agent now resolves to `feral/current` via the config. No change to the SSE streaming path.

## `agents::run()` — Kept as Silent Fallback

Not removed. `run_agent` in `lib.rs` keeps its dispatch:

```rust
if cfg.preferred_runtime.as_deref() == Some("openclaw") {
    openclaw::run_openclaw(cfg, prompt)
} else {
    agents::run(cfg, prompt, state.manager.clone())
}
```

Agents without `preferred_runtime = "openclaw"` (e.g. legacy agents) still work via the local runner. Not surfaced in UI.

## Error Handling

| Scenario | Behaviour |
|---|---|
| Feral API fails to bind port 11435 | Log warning, proceed — OpenClaw will return connect errors surfaced in AgentRunPanel |
| OpenClaw sidecar fails to start | Existing behaviour: agents fall back to `agents::run()` (local) |
| Config write fails | Log error, proceed without config — OpenClaw starts with its default config |
| Warmup fails in DoneStep | Show "Load a model" message — not a hard error |

## What Does Not Change

- `openclaw_connection.rs` — load/save/clear commands unchanged
- `openclaw.rs` — detect, status, open_docs, test_message, test_agent_message, warmup_agent all unchanged
- `openclaw_sidecar::generate_token`, `probe_path`, `bundled_binary_path` — unchanged
- All existing agent JSON files on disk — backward compatible (`preferred_runtime` defaults to `null`)
