**Date:** 2026-08-19 · **Branch:** `ui/cinematic-shell` · **Type:** evidence, not design.

Strictly constative record of what exists in `FeralAgent/src/brain/` and its call
sites today. Every claim carries a file reference. **No solutions are proposed
here** — gaps are stated as gaps and nothing more. Input document for the Phase 1
spec; do not edit this file to match later design decisions.

## 2. Contracts that already exist

**Capability vocabulary** — `capability-registry.ts:38`

```
Capability = "reasoning" | "coding" | "vision" | "speed" | "multilingual"
```

Scores are `0..10` per key. Missing keys default to `0` via
`normalizeCapabilities()` (`capability-registry.ts:170`) — a model with an
unstated capability is treated as bad at it, not average.

**Task vocabulary** — `capability-registry.ts:50`

```
Category = "simple" | "coding" | "vision" | "reasoning" | "creative"
         | "multilingual" | "offline"
```

**Model shape** — `BrainModel`, `capability-registry.ts:60`

```
{ id, target: ModelTarget, capabilities: Record<Capability, number>,
  cost: 1 | 2 | 3, local: boolean }
```

`target` reuses the real `ModelTarget` the inference router already accepts, so
routing output feeds `router.completeWith()` with no cast.

**Requirement table** — `brain-stack.ts:90`

```
coding:       { coding: 1.0, reasoning: 0.5 }
vision:       { vision: 1.0 }
reasoning:    { reasoning: 1.0 }
creative:     { multilingual: 0.4, reasoning: 0.3, speed: 0.2 }
simple:       { speed: 1.0 }
offline:      { speed: 0.5 }
multilingual: { multilingual: 1.0 }
```

**Evidence:** a task-requirement vector matched against a per-model capability
vector, producing a ranking, is already the implemented architecture. The score is
`Σ requirement[cap] × capabilities[cap]`, adjusted by cost and confidence.

**Gap:** the vocabulary has five keys. It contains no `tool_use`, no
`structured_output`, no `context_length`, and no memory/hardware requirement.

## 3. How Brain activates today

`brain-config.ts:defaultBrainPath()` resolves `$FERAL_HOME/brain.json`, else
`~/.feral/brain.json`.

- File absent and `FERAL_BRAIN` unset → `loadBrainConfig()` returns `null`.
- File present → its own `enabled` flag decides.
- `FERAL_BRAIN=1` → force-enable; **throws** if the file is missing.

Wiring, `boot.ts:987`:

```
const brainCfg = loadBrainConfig();
const brain = brainCfg ? new BrainStack(brainCfg, new CircuitBreaker()) : null;
```

`brain` is passed into `AgentLoop` (`boot.ts:997`) and exposed to the `self_*`
introspection tools as `brainStackEnabled` (`boot.ts:1851`).

**Evidence — the comment at `boot.ts:983` states the consequence in the source
itself:** *"production runs with no brain.json see no behavior change."*

**Gap:** nothing in the product writes `brain.json`. Searched: `cli.ts` has a
`setup` command (`cli.ts:88`) and a `brain` command documented at `cli.ts:24` as
*"(stub)"*; neither writes the file. No Tauri command, no onboarding step, no
first-run default creates it. `brain.example.json` claims *"`feral setup` writes
this shape for you"* — that claim does not match the code.

---

## 4. Defaults

`loadBrainConfig()` applies **no defaults**. It validates and throws:

- `enabled` must be boolean
- `mode` must be `budget | balanced | quality`
- `registry` must be an array

A malformed file is treated as a config bug, not a runtime condition.

**Gap:** there is no default configuration at any level. The absence of the file
is the off switch, and there is no "sensible starting registry" anywhere in the
codebase.

## 5. Task classification

`classify()` is pure — no I/O, no extra model call. First match wins
(`task-classifier.ts:141-170`):

1. `hasImages` → `vision` (confidence `0.95`)
2. `offline` hint → `offline` (`0.95`)
3. code fences / coding verbs → `coding` (`0.75`)
4. reasoning cues or prompt > 1500 chars → `reasoning` (`0.75`)
5. creative cues → `creative` (`0.75`)
6. otherwise → `simple` (`0.5`)

Keyword sets are exported as `RegExp[]` and use word boundaries specifically to
avoid substring false positives ("showy"/"why", "improve"/"prove").

`offline` is not detected by the classifier — it is a caller-supplied fact.
`agent-loop.ts:2231` computes it as
`router.isPrimaryLocal && !router.cloudReachable`.

**Gap — `multilingual` is unreachable.** `Category` declares it
(`capability-registry.ts:50`), `REQUIREMENTS` weights it at `1.0`
(`brain-stack.ts:99`), and the scorer is tested against it
(`brain-stack.test.ts`, *"multilingual-strong beats coding-strong"*). But
`classify()` has six return sites and none of them emits `"multilingual"`. No
input can currently produce that category. As a result the `multilingual`
capability score on every registered model influences routing only through the
`creative` weight of `0.4`.

## 6. How the capability registry is constructed

It is not constructed from anything. `CapabilityRegistry` takes a
`BrainModel[]` in its constructor (`capability-registry.ts:88`) and validates
only that ids are unique. That array comes from `BrainConfig.registry` — i.e.
from the JSON file the user hand-writes.

`brain.example.json` shows the expected authoring effort per model:

```
"capabilities": { "reasoning": 5, "coding": 6, "vision": 0,
                  "speed": 8, "multilingual": 5 },
"cost": 1, "local": true
```

**Gap:** there is no discovery, no derivation from model metadata, no mapping
from installed local models or configured cloud keys, and no default table by
model family. Capability numbers exist only where a human typed them.

Related evidence: the desktop app already holds real local-model metadata —
`frontend-react/src/lib/tauri/index.ts:67-72` exposes `ctx_len`, `n_ctx_train`,
`size_bytes`, `quant`, `loaded`. None of it reaches `src/brain/`.

## 7. Routing modes

`Mode = "budget" | "balanced" | "quality"` (`brain-stack.ts:65`).

| Constant | budget | balanced | quality |
|---|---|---|---|
| `MODE_WEIGHT` (cost penalty) | 2.0 | 1.0 | 0 |
| `LOCAL_BONUS` | applied (1.5) | not applied | not applied |

`CONFIDENCE_WEIGHT` is `0.5` — classifier confidence acts only as a tiebreaker.

**Gap:** the mode is a static field in the config file. Nothing selects it at
runtime, and nothing in the UI sets it.

## 8. Which models are eligible

`available(isHealthy)` (`capability-registry.ts:128`) admits a model iff both:

1. `isConfigured(model)` — local models are configured by definition; cloud
   targets require a non-empty `apiKey`. An empty string counts as unconfigured.
2. `isHealthy(model.id)` — the circuit breaker is closed or half-open.

The scorer never sees unhealthy or unconfigured models.

**Evidence:** a runtime-health input into model selection already exists, and it
is already keyed by `BrainModel.id`. The breaker instance is created per
`BrainStack` at `boot.ts:988`; model health and tool health are separate
namespaces.

**Gap:** the breaker is binary (open/closed). No observed statistics — tool-call
success rate, structured-output success rate, latency, completion rate — feed
back into selection. `isConfigured` checks credential presence only; it performs
no capability, context-window, or hardware feasibility check.

## 9. Where the flow stops

Routing order (`brain-stack.ts:26-42`): classify → look up requirements →
`available()` → per-category override → `offlineModelId` force → score → pick
top → choose a fallback, preferring a **different provider family** so one
outage cannot take out both targets.

With no candidates, `route()` throws `BrainError` — it never silently picks a
broken model.

But the caller swallows it. `agent-loop.ts:2239-2245`:

```
} catch (err) {
  console.warn(`[brain] route failed, falling back to router defaults: ${err}`);
  return null;
}
```

**Evidence:** Brain is fully wired into the turn. `agent-loop.ts:1159` calls
`#routeForTurn` on every turn when `#brain` is non-null; the result is handed to
`router.completeWith()`.

**Gap:** a routing failure is visible only as a `console.warn`. The user sees the
default path's behaviour with no explanation of why the chosen model was not
used. This matches the failure shape recorded in `CLAUDE.md` — *the message only
one person can read*.

## 10. Fresh install

On a machine with no `~/.feral/brain.json`, no local model, and no cloud key:

- `loadBrainConfig()` → `null`
- `brain` → `null`
- `#routeForTurn` → `null` on every turn (`agent-loop.ts:2228`)
- Inference falls through to `router.complete()` with `#primary` / `#fallback`
- The desktop UI renders `NoModelEmptyState` and the composer placeholder
  `chat.placeholder.noModel` — *"Load a model or add a cloud key to start
  chatting"* (`frontend-react/src/lib/i18n.ts:20`)

**Gap:** every installation of Feral that has ever shipped runs with model
routing off. Not degraded — absent. There is also no state in which the product
distinguishes *"no model configured"* from *"models exist but routing is off"*;
both present as the same empty state.

## 12. Assumptions already encoded in the code

Recorded because Phase 1 will either inherit or deliberately overturn each one.

1. **Brain Stack is opt-in.** Stated in `brain-stack.ts:107` and enforced by
   file presence.
2. **A missing capability means bad at it, not unknown.** `normalizeCapabilities`
   fills `0`.
3. **Capability is a single scalar per axis.** No confidence, no provenance, no
   observation count attached to a score.
4. **Credentials are the only readiness signal.** `isConfigured` is documented as
   the extension point for anything more.
5. **Health is binary and external.** `BrainStack` deliberately does not own the
   breaker; it asks a callback.
6. **Classification needs no model.** Explicitly a non-goal in the source: a
   local-LLM classifier was ruled out for MVP.
7. **Cost is a three-step ordinal**, not a price. `1 = local/cheap`,
   `2 = mid`, `3 = premium`.
8. **The requirement table is hand-tuned and read-only.** `brain-stack.ts:84`
   marks per-capability user overrides as a later slice.
9. **A routing failure is recoverable and silent.** The agent loop treats it as a
   fallback condition, not an error to surface.

---

## Summary of gaps, as gaps

1. Nothing writes `brain.json`; `brain.example.json` documents a `feral setup`
   behaviour that does not exist.
2. No defaults at any level — absence of the file is the off switch.
3. No source of capability values other than a human typing them.
4. Vocabulary lacks `tool_use` and `structured_output`.
5. No hard-constraint concept: context window and hardware feasibility cannot be
   expressed, only scored.
6. `multilingual` is a declared, weighted, tested category that no input can
   produce.
7. Local-model metadata the app already holds (`ctx_len`, `size_bytes`, `quant`)
   never reaches `src/brain/`.
8. Runtime health is binary; no observed performance feeds selection.
9. Routing failure is reported only to the console.
10. Mode is static and unreachable from the UI.
